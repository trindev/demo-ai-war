# แยกถูก รับถึงบ้าน (เดโม)

สมาชิกถ่ายรูปถุงขยะรีไซเคิล → AI นับถุง แยกชนิด และนับชิ้นในแต่ละถุง → แจ้งรับแล้วได้ป้ายของแต่ละถุงกับ QR → ระบบจัดเส้นทางรถตามหมุดและเวลานัด → คนขับนำทางไปตามแผนที่ สแกน QR ยืนยันจุด แล้วตรวจรับทีละถุงตามป้ายพร้อมน้ำหนักจริง → ส่งของที่ศูนย์คัดแยก → ส่งต่อโรงงาน

## วิธีรัน

```bash
docker compose up -d --build
```

เปิด <http://localhost:8000> แล้วเลือกบัญชีตัวอย่างจากหน้าเข้าสู่ระบบ

เปิดใช้ AI จริง: คัดลอก `.env.example` เป็น `.env` ใส่ `ANTHROPIC_API_KEY` แล้วรัน `docker compose up -d` อีกครั้ง
ถ้าไม่ใส่ key ระบบใช้ผลแบบจำลอง (ไม่ได้อ่านจากรูป) และแสดงป้าย "AI: โหมดจำลอง"

## บทบาทและบัญชีตัวอย่าง

หน้าเข้าสู่ระบบมีปุ่มเข้าใช้งานด่วนของทุกบทบาท และเข้าด้วยชื่อผู้ใช้กับรหัสผ่านได้
รหัสผ่านของบัญชีตัวอย่างทุกบัญชีคือค่าของ `DEMO_PASSWORD` (ค่าตั้งต้น `demo1234`) ปิดปุ่มด่วนได้ด้วย `DEMO_QUICK_LOGIN=0`

| บทบาท | บัญชีตัวอย่าง | หน้าที่เห็น |
|---|---|---|
| สมาชิก (`user`) | `somchai`, `prasert`, `company1` (บริษัท) | แจ้งรับ, ราคา, ลดคาร์บอน |
| คนขับ (`driver`) | `driver1`, `driver2` | งานของฉัน (แผนที่ รายการจุดจอด โหมดนำทาง), ราคา |
| ผู้ดูแลระบบ (`admin`) | `admin` | แดชบอร์ด, เกณฑ์รับของ, ราคา, คู่ค้า, คาร์บอน, บันทึก |
| คู่ค้า (`partner`) | `factory1` (โรงงาน), `shop1` (ร้านรับซื้อ) | พอร์ทัล, ราคา |

ทุกเส้นทางของ API ตรวจสิทธิ์จาก session cookie และข้อมูลที่ส่งกลับถูกกรองตามบทบาท เช่น สมาชิกเห็นเฉพาะคำขอของตัวเอง และเปิด QR ได้เฉพาะคำขอของตัวเอง

## หลังบ้านของผู้ดูแล

หน้าของผู้ดูแลใช้ธีมแดชบอร์ดสีเข้ม เมนูอยู่แถบด้านข้างบนจอกว้าง

**แดชบอร์ด:** การ์ดสรุปงานวันนี้ วงแหวนสัดส่วนวัสดุที่รอรับ แถบการใช้พื้นที่รถ รายการที่ต้องดูแล กราฟน้ำหนักที่รับจริงรายสัปดาห์ แผนที่เส้นทางของรถทุกคัน สั่งจัดรถด้วยภาษาพูด รายการแจ้งล่าสุด ปริมาณที่ต้องส่งแต่ละโรงงาน และรายการกรณีผ่อนปรนหรือต้องตรวจ

**เกณฑ์รับของและการผ่อนปรน** มีผลกับระบบทันทีเมื่อบันทึก:

| เกณฑ์ | ผล |
|---|---|
| วัสดุที่รับ ราคา น้ำหนักต่อชิ้น | วัสดุที่ปิดรับขึ้นป้าย "ไม่รับ" และไม่ถูกนับน้ำหนักหรือมูลค่า |
| น้ำหนักรวมขั้นต่ำ | ต่ำกว่าขั้นต่ำ: ไม่รับ หรือผ่อนปรนให้รับแล้วติดธง |
| ถุงที่ของปนกัน | รับตามปกติ รับแต่ติดธง หรือไม่รับ |
| ระยะจากหมุดตอนสแกน QR | ไกลเกินระยะ: ไม่ให้ยืนยันจุด หรือผ่อนปรนแล้วติดธง |
| รับบางส่วน | ถ้าปิด คนขับต้องพบครบทุกถุง |
| น้ำหนักจริงต่างจากที่ประเมิน | ต่างเกินเปอร์เซ็นต์ที่ตั้ง: ติดธงให้ตรวจ |
| แต้มต่อกิโลกรัม ราคาคาร์บอน เส้นทางตามถนน | ใช้กับแต้ม หน้าคาร์บอน และโหมดนำทาง |

**กระดานราคา:** ราคารับซื้อสูงสุดของแต่ละวัสดุ ทิศทางราคาเทียบเมื่อวาน กราฟย้อนหลัง 7, 30 และ 60 วัน และราคาของคู่ค้าแต่ละราย คู่ค้าตั้งราคาของวันนี้เองได้จากพอร์ทัล

ที่มาของราคา: ประวัติราคาเป็นข้อมูลจำลอง สุ่มให้อยู่ในช่วงของราคาอ้างอิงจากภายนอก (`PRICE_REFS` ใน `app/config.py`) คือ Sanook News 28 ต.ค. 2568 และราคากลางของวงษ์พาณิชย์ ณ 9 พ.ค. 2565 ที่กรุงเทพธุรกิจอ้าง ทั้งสองเป็นราคาในอดีต ใต้กราฟมีตารางแหล่งอ้างอิงพร้อมลิงก์ และราคาของคู่ค้าแต่ละรายติดป้ายว่าเป็น "ข้อมูลจำลอง" หรือ "คู่ค้าบันทึกเอง"

**คู่ค้า:** ข้อมูลติดต่อ วัสดุที่รับ ราคาล่าสุด ปริมาณที่คาดว่าจะส่ง และส่งข้อความแจ้งเตรียมรับของ ซึ่งคู่ค้ากดรับทราบได้จากพอร์ทัล

## ขั้นตอนของคนขับ

1. หน้า "งานของฉัน" แสดงแผนที่เส้นทางของรอบนี้พร้อมหมุดทุกจุด แตะหมุดเพื่อดูรายละเอียดเบื้องต้น
2. กด "นำทาง" เพื่อเข้าโหมดนำทางเต็มจอ เห็นเส้นทาง ระยะทาง เวลาโดยประมาณ ป้ายถุงของจุดนั้น ปุ่มโทรหาลูกค้า และปุ่มเปิดใน Google Maps
3. ถึงจุดแล้วสแกน QR จากมือถือของสมาชิก เลือกได้ 3 ทาง: เปิดกล้อง แนบรูป QR หรือพิมพ์รหัส 6 ตัว ระบบปฏิเสธ QR ของจุดอื่น
4. ตรวจรับทีละถุงตามป้าย เช่น `21-A` ปิดสวิตช์ถ้าไม่พบถุง ติ๊ก "ของไม่ตรง" ถ้าของไม่ตรงกับที่แจ้ง ใส่น้ำหนักจริงของแต่ละถุง
5. รับครบแล้วนำทางกลับศูนย์คัดแยก และกด "ส่งของที่ศูนย์แล้ว" เพื่อปิดรอบ

สถานะของคำขอ: รอรับ → ยืนยันจุดแล้ว → รับแล้ว → ส่งถึงศูนย์แล้ว

## บริษัทและคาร์บอน

สมาชิกประเภทบริษัทใช้ขั้นตอนแจ้งรับเดียวกัน หน้า "ลดคาร์บอน" แสดงน้ำหนักที่ส่งรีไซเคิลแล้ว ตัวเลขคาร์บอนสองชุด แยกตามวัสดุและรายเดือน และมีเครื่องคำนวณสำหรับประเมินก่อนทำสัญญา ผู้ดูแลเห็นของทุกสมาชิกและดาวน์โหลด CSV ได้

ตัวเลขคาร์บอนมีสองชุด แสดงแยกกันทุกที่ (หน้าเว็บ, CSV, API) และไม่นำมาหักกัน:

| ตัวเลข | ช่องใน API | ความหมาย | ที่มาของค่าปัจจัย |
|---|---|---|---|
| ที่หลีกเลี่ยงได้ | `co2e_kg` | ผลดีเมื่อเทียบกับการผลิตจากวัตถุดิบใหม่ ใช้เป็นข้อมูลประกอบ | US EPA WARM รุ่น 16 (ผู้ดูแลแทนค่าได้) |
| ที่ปล่อยจากกระบวนการรีไซเคิล | `recycling_co2e_kg` | สิ่งที่บริษัทลงบัญชีก๊าซเรือนกระจกขององค์กร Scope 3 หมวด 5 | US EPA GHG Emission Factors Hub 2025 ตารางที่ 9 คอลัมน์ Recycled (ค่าคงที่ใน `app/config.py`) |

- ปัจจัยที่ใช้คือค่าการปล่อยสุทธิของการรีไซเคิลจาก US EPA WARM รุ่น 16 (`app/config.py`) เป็นค่าของสหรัฐฯ
- ตัวเลขนี้เป็นประมาณการสำหรับรายงานภายในและงาน ESG ยังไม่ใช่คาร์บอนเครดิต การขอคาร์บอนเครดิต เช่น T-VER ของ อบก. ต้องขึ้นทะเบียนโครงการ ใช้ระเบียบวิธีที่รับรอง และผ่านการทวนสอบ
- ราคาคาร์บอนที่ใช้ตีมูลค่าเป็นค่าสมมติ แก้ได้ที่หน้าเกณฑ์รับของ

### ค่าปัจจัยจาก อบก. และ API สำหรับระบบภายนอก

ผู้ดูแลแทนค่าปัจจัยตั้งต้นด้วยค่าจาก อบก. หรือแหล่งอื่นได้ ทั้งจากหน้าคาร์บอนและผ่าน API ระบบไม่ได้ดึงค่าจาก อบก. เอง ต้องมีคนหรือระบบส่งค่าเข้ามา
ระบบภายนอกเรียก API ด้วยโทเคนของระบบในส่วนหัว `Authorization: Bearer <โทเคน>` ผู้ดูแลสร้างและยกเลิกโทเคนได้ที่หน้าคาร์บอน ตัวโทเคนแสดงครั้งเดียวตอนสร้าง ฐานข้อมูลเก็บเฉพาะค่า hash

| เส้นทาง | สิทธิ์ของโทเคน | ใช้ทำอะไร |
|---|---|---|
| `GET /api/v1/carbon/summary` | `carbon:read` | ยอดรวม รายเดือน และรายสมาชิก |
| `GET /api/v1/carbon/members/{id}` | `carbon:read` | ข้อมูลของสมาชิกรายเดียว |
| `GET /api/v1/carbon/factors` | `carbon:read` | ค่าปัจจัยที่ใช้อยู่และที่มา |
| `PUT /api/v1/carbon/factors` | `carbon:write` | ส่งค่าปัจจัยชุดใหม่ ต้องระบุ `source` |
| `DELETE /api/v1/carbon/factors` | `carbon:write` | กลับไปใช้ค่าตั้งต้น |

โทเคนผูกกับสมาชิกรายเดียวได้ (เช่น ให้บริษัทดึงข้อมูลของตัวเอง) ซึ่งจะเห็นเฉพาะข้อมูลของสมาชิกรายนั้นและใช้ได้เฉพาะสิทธิ์อ่าน

```bash
curl -H "Authorization: Bearer <โทเคน>" http://localhost:8000/api/v1/carbon/summary
```

### ส่งเข้าบัญชีคาร์บอน GrowGreen

บริษัทเชื่อมบัญชีกับองค์กรของตัวเองใน GrowGreen ได้จากหน้า "ลดคาร์บอน" โดยใส่ API key (ต้องมีสิทธิ์ `activity:write`) และรหัสสถานที่
เมื่อรถส่งของถึงศูนย์คัดแยก ระบบส่งน้ำหนักจริงแยกตามวัสดุไปที่ `POST /ext/activity-data` ของ GrowGreen เป็นเอกสารร่างในหมวด 3-5-3 การรีไซเคิลของเสีย

- ส่งเฉพาะกิโลกรัม ไม่ส่งตัวเลข CO2e GrowGreen คำนวณการปล่อยด้วยค่าปัจจัยของตัวเอง
- คำตอบที่สำเร็จของ GrowGreen ห่ออยู่ใน `{"data": ...}` ทดสอบกับระบบจริงแล้วเมื่อ 24 พ.ย. 2569
- เอกสารที่ได้เป็นร่าง ต้องมีคนของบริษัทตรวจและกดส่งอนุมัติใน GrowGreen ระบบนี้ส่งอนุมัติแทนไม่ได้
- คำขอที่ติดธง "ของไม่ตรง" หรือ "น้ำหนักต่างเกินเกณฑ์" ไม่ถูกส่งอัตโนมัติ ต้องมีคนกดส่งเอง
- การรับหนึ่งครั้งใช้เลขอ้างอิง `YT-<เลขคำขอ>-<รหัสรับของ>` เป็นทั้ง `referenceNo` และ `Idempotency-Key` GrowGreen จึงปฏิเสธการส่งซ้ำ
- การส่งที่ไม่สำเร็จถูกบันทึกพร้อมเหตุผล และกด "ส่งใหม่" ได้ การปิดรอบของคนขับไม่รอผลการส่ง
- ผู้ดูแลเห็นสถานะของทุกบริษัทที่หน้า "คาร์บอน" และกดส่งแทนได้

ที่อยู่ของ GrowGreen ตั้งที่เซิร์ฟเวอร์ด้วย `GROWGREEN_API_URL` ในไฟล์ `.env` (ลงท้ายด้วย `/api/v1`) แล้วรัน `docker compose up -d` อีกครั้ง สมาชิกตั้งที่อยู่เองไม่ได้
ถ้าไม่ได้ตั้งค่า ระบบทำงานในโหมดดูตัวอย่าง: แสดงข้อมูลที่จะส่ง แต่ไม่ส่งจริง
ใส่ `GROWGREEN_API_KEY` ใน `.env` ด้วยได้ บริษัทที่กดเชื่อมต่อโดยไม่ใส่ key ของตัวเองจะใช้ key นี้ (เหมาะกับเดโมที่มีองค์กรเดียว) ถ้าองค์กรมีสถานที่เดียว ระบบเติมรหัสสถานที่ให้เอง

| วัสดุของระบบนี้ | รหัสกิจกรรมใน GrowGreen |
|---|---|
| ขวด PET, HDPE, พลาสติกอื่น ๆ | `RCY_MIXED_PLASTIC` |
| กระดาษลัง | `RCY_CARDBOARD` |
| กระดาษ | `RCY_MIXED_PAPER` |
| กระป๋องอะลูมิเนียม | `RCY_ALUMINIUM_CAN` |
| กระป๋องเหล็ก/โลหะ | `RCY_MIXED_METAL` |
| ขวดแก้ว | `RCY_GLASS` |

## AI อยู่ตรงไหน

1. **นับถุง แยกชนิด และนับชิ้นจากรูป** (`app/ai.py`): Claude Vision ตอบเป็น JSON ตาม schema เป็นถุงหรือถังทีละใบ แต่ละใบมีชนิดวัสดุ จำนวนชิ้น คำแนะนำก่อนส่ง ขนาด และบอกว่านับครบหรือนับโดยประมาณ หนึ่งรูปมีได้หลายถัง
2. **สั่งจัดรถด้วยภาษาพูด** (`app/ai.py`): Claude แปลคำสั่งเช่น "รถคัน 2 เสีย" เป็น action ของระบบ

การคำนวณเส้นทาง (`app/routing.py`) ใช้ OR-Tools ไม่ใช่ LLM น้ำหนัก มูลค่า และคาร์บอนคำนวณที่เซิร์ฟเวอร์จากตารางใน `app/config.py` และเกณฑ์ที่ผู้ดูแลตั้ง

## โครงสร้าง

```
app/main.py      API ทุกเส้นทาง การตรวจสิทธิ์ตามบทบาท และเสิร์ฟหน้าเว็บ
app/auth.py      เข้าสู่ระบบ session cookie บทบาท และโทเคนของระบบ
app/settings.py  เกณฑ์รับของและการผ่อนปรนที่ผู้ดูแลแก้ได้
app/ai.py        เรียก Claude (นับถุงและแยก, แปลคำสั่ง) พร้อมโหมดจำลอง
app/routing.py   จัดเส้นทางรถแบบมีเวลานัดและความจุ
app/estimate.py  จำนวนชิ้นเป็นน้ำหนักและมูลค่า
app/carbon.py    ประมาณการก๊าซเรือนกระจกที่หลีกเลี่ยงได้ และค่าปัจจัยที่แก้ได้
app/growgreen.py ส่งน้ำหนักที่รับจริงของบริษัทเข้า GrowGreen เป็นเอกสารร่าง
app/config.py    ค่าตั้งต้น: วัสดุ ราคา ขนาดถุง ช่วงเวลา ศูนย์คัดแยก ปัจจัยคาร์บอน
tests/           ทดสอบการเชื่อมต่อ GrowGreen และตัวเลขคาร์บอนสองชุด
app/seed.py      ข้อมูลตัวอย่าง: สมาชิก บริษัท รถ คำขอ คู่ค้า ประวัติราคา บัญชี
web/app.js       หน้าสมาชิก แดชบอร์ด คนขับ บันทึก
web/portal.js    เข้าสู่ระบบ เมนูตามบทบาท ราคา เกณฑ์ คู่ค้า คาร์บอน แผนที่และโหมดนำทาง
web/             index.html, styles.css, sw.js, manifest
```

แก้ไฟล์ใน `app/` หรือ `web/` แล้วเห็นผลทันทีโดยไม่ต้อง build ใหม่

รันชุดทดสอบในคอนเทนเนอร์ (ใช้ฐานข้อมูลชั่วคราว ไม่แตะข้อมูลของเดโม):

```bash
docker cp tests "$(docker compose ps -q web)":/srv/tests
docker compose exec web python -m unittest discover -s tests
```

## ข้อจำกัดของเดโม

- ข้อมูลทั้งหมดเป็นข้อมูลสมมติ รวมถึงชื่อ เบอร์โทร อีเมลของคู่ค้า และประวัติราคา
- การจัดรอบรถคิดระยะจากเส้นตรงคูณ 1.35 และความเร็วเฉลี่ย 22 กม./ชม. ส่วนโหมดนำทางของคนขับใช้เส้นทางตามถนนจากบริการ OSRM สาธารณะ ซึ่งส่งพิกัดต้นทางและปลายทางออกไปภายนอก ผู้ดูแลปิดได้ที่หน้าเกณฑ์รับของ และควรเปลี่ยนเป็นบริการของตัวเองก่อนใช้จริง
- ราคารับซื้อ น้ำหนักต่อชิ้น ตำแหน่งศูนย์คัดแยก และโรงงาน เป็นค่าตัวอย่าง
- การเข้าสู่ระบบเป็นแบบเดโม: บัญชีตัวอย่างใช้รหัสผ่านร่วมกัน ไม่มีการสมัครสมาชิก การรีเซ็ตรหัสผ่าน หรือการจำกัดจำนวนครั้งที่ลองผิด
- API key ของ GrowGreen เก็บในฐานข้อมูลของเดโมโดยไม่ได้เข้ารหัส (ไม่ส่งกลับไปที่หน้าเว็บ) ก่อนใช้จริงควรเก็บในที่เก็บความลับ
- ค่าปัจจัยของการปล่อยจากกระบวนการรีไซเคิลเป็นค่าคงที่ ยังแก้จากหน้าเว็บไม่ได้
- การเปิดกล้องสแกน QR การติดตั้ง PWA และตำแหน่งปัจจุบัน ใช้ได้เฉพาะบน `localhost` หรือ HTTPS
